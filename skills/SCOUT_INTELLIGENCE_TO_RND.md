# SKILL — SCOUT INTELLIGENCE TO R&D

## Trigger
Use when a Scout/source discovers a new video, article, repository, paper, tool, benchmark, competitor move, customer pattern or technical method that may affect Project $10M.

## Goal
Convert the signal into the smallest useful decision/experiment while preserving truthfulness and provenance.

## Procedure

### Step 1 — Capture
Record source, title/link, date, topic, and why it may matter.

### Step 2 — Bullet extraction
Write 3–10 concise bullets:
- what happened / what was claimed
- mechanism
- evidence presented
- assumptions
- limitations
- counterevidence if known

### Step 3 — Classify each important claim
Use exactly:
VERIFIED FACT / FIRSTHAND CLAIM / SOURCE CLAIM / INFERENCE / HYPOTHESIS / FORECAST / OPINION / UNKNOWN

### Step 4 — Relevance
Map only relevant layers:
Data / Workflow / Integration / Evaluation / Distribution / Permissions / Audit / Customer Relationship / Revenue / Time Compression.

### Step 5 — Ask the AGIS questions
- What changes if this is true?
- What breaks if this is false?
- Does an existing Core Agent already cover this?
- Can better context/skill/tool solve it without a new Agent?
- What is the smallest falsifiable experiment?
- What metric decides pass/fail?
- What is the cost of testing?
- What reusable asset might result?

### Step 6 — Route
Choose one:
R&D / JOB / EVAL / SKILL CANDIDATE / CUSTOMER-PRODUCT INSIGHT / WATCH / NO ACTION

### Step 7 — Review
QA/EVAL reviews anything that could materially change:
- agent behavior
- architecture
- security/permissions
- customer claims
- $10M math
- production workflow

### Step 8 — Feedback
When downstream work resolves:
- write result back to the Scout Signal
- update source usefulness
- extract lesson only if evidence supports it

## Anti-patterns
Do not:
- copy full transcripts into learning storage by default;
- create an Agent for every topic;
- convert a forecast into a fact;
- create work because a clip sounded exciting;
- promote a skill from one untested example;
- count quantity of Scout links as learning velocity.

## Done
A Scout signal is done when it is:
- PROMOTED with downstream ID and measurable next step, or
- WATCH with explicit revisit condition, or
- NO ACTION with explicit reason.
